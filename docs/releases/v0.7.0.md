# CPC Validation v0.7.0

Release date: **2026-10-26**. Release tag: `v0.7.0`.

CPC-SHOR is a core CPC research and validation program. This release integrates
its finite software, pre-physical N0 tooling, bounded P3/P4 work and the completed
classical UP5K/Pico milestone into the main CPC history. It preserves the
RFC-0001 through RFC-0010 architecture and the separation between compilation,
execution, observation, decoding and independent semantic validation.

## Architecture and RFC-0010

The [accepted RFC-0010](../design/RFC-0010-Driven-Dissipative-Open-System-Execution-and-Referenced-Readout.md)
and [architecture overview](../architecture.md) retain the driven-dissipative
open-system execution and referenced-readout obligations introduced in v0.6.0:
admissibility, stabilization/problem-generator provenance, terminal silence,
fixed/dark-state conditions, convergence, calibration and independent validation.
The [execution specification](../../src/open_system_execution.py),
[conformance layer](../../src/open_system_conformance.py) and
[simulated reference witness](../../src/open_system_reference.py) remain software
realizations. Passing these contracts does not establish a physical open-system
substrate or quantum execution.

## CPC-SHOR and finite Shor models

The [core research overview](../shor/README.md) connects modular-response
representations, finite open-system witnesses, coherence negative controls,
Fourier readout, decoding and independent order/factor validation.
The [finite RFC-0010 prototype](../shor-rfc0010-prototype.md) distinguishes
collective semantic-reference, which-x decoherence-control and circuit-clock
witnesses from the constraint-description-only native multiplication tree.

A retained density-matrix/circuit-clock simulation recovered N=15, a=2, Q=16,
r=4 and factors 3 and 5 using 256 simulated shots. This is finite classical
simulation of the declared quantum model, not physical Shor factorization.
Explicit path enumeration, finite dimensions, precision and simulator costs
remain part of the model; no scalable native implementation follows.

Historical single-node, two-node and cleanup/locality notes remain archival
research checkpoints, not current execution authorization or a promise that
unpublished launchers/results are included.

## N0 pre-physical work and WP-B1

[N0](../shor/n0-status.md) includes finite bosonic models, profile/raw-record
contracts, calibration and device boundaries, synthetic statistical rehearsal,
fault/reduction/claim gates, preregistration/readiness infrastructure and
controller software/RTL. Apparatus status remains **D**: no physical N0 quantum
measurement or acquisition is established.

[WP-B1 full bosonic software conformance](../shor/wp-b1-conformance-checklist.md)
remains **OPEN**; existing reusable components are not a completed end-to-end
vendor/bosonic CCIR conformance chain. The
[Alice & Bob technical collaboration brief](../shor/alice-bob-collaboration-brief.md)
remains an **UNSENT draft**. Software publication grants no device authorization.

Pico PIO provides deterministic nanosecond-scale clock granularity. This is not
independently measured end-to-end nanosecond precision in a quantum control loop.

## Bounded P3/P4 software

Published P3 components cover bounded model/compiler construction,
inference/analysis, classical host filtering and guarded execution/provenance.
P4 includes deterministic arithmetic/reconstruction, separate EXACT and
bounded-error certification/risk contracts, retained-record replay, guarded
acquisition adapters, diagnostic-state construction, per-trial retained-artifact
calibration scoring and a classical host C simulation kernel.

EXACT and bounded-error guarantees remain distinct. Bounded-error certification
does not require factorization of the candidate order; its stated risk is a
joint-event bound under its assumptions, not automatically a conditional error
bound given acceptance. Per-trial scoring is not a calibration PASS.

The complete historical autonomous P4 workflow, calibrated-population registry,
deferred evidence/reducer/supervisor modules and historical launchers remain
excluded. E5-v1 remains consumed, non-retryable and
INCOMPLETE_OR_INVALID_GRID. E5-R1 is post hoc recovery, not a retrospective grid
PASS. Historical acceptance criteria are not newly observed results.

## Known failures and limits

Unseeded physical record **217** retains status **0022** versus frozen oracle
**0002**. Records **200, 206, 215 and 219** also lack established oracle-exact
physical passes. Earlier consumed transport/CRC failures and the historical
Phase-E discrepancy are not erased or assumed resolved by the three seeded
successes. No oracle expectations or response/PRNG ordering were changed.

The [historical RFC-0009 P1 physical evidence](../../evidence/p1/physical/README.md)
is a separate lineage and remains unchanged. The seven frozen DYADIC-PHASE
documents retain exact bytes and 34 intentional Markdown hard breaks, protected
by seven exact-path whitespace attributes and
[SHA/count/negative-policy regression tests](../../tests/test_frozen_markdown_whitespace.py).

Physical N0 quantum execution, physical Shor factorization, native scalable
quantum order finding, scalable quantum computing, quantum advantage and ASI
containment are **not demonstrated**. Classical host execution, RTL simulation,
software conformance and the FPGA/Pico service do not substitute for those
physical claims.

## Reproduction and release validation

Use Python 3.12+ and the locked Python dependencies. The complete suite also
requires the applicable C compiler/libm, ngspice, Icarus Verilog/vvp and Yosys.
The commands below validate software and retained public evidence; they perform
no physical device operation.

~~~bash
git clone https://github.com/GridSAT/cpc-validation.git
cd cpc-validation
git checkout v0.7.0
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-lock.txt
python validate.py --full
python -B verify_up5k_physical_evidence.py
git diff --check v0.6.0 HEAD
~~~

The [contribution rule](../../CONTRIBUTING.md) requires the complete twelve-stage
profile against each exact prospective commit before commit creation, including
metadata/documentation commits. Release qualification additionally requires a
fresh isolated checkout with a new locked environment, evidence integrity,
documentation links, privacy review, preserved history and frozen-record checks.
The per-commit ledger, actual test counts, exact tag target/tree and source
archive digest are retained in private release-verification evidence and
reported with publication. Prior release test counts remain historical.
