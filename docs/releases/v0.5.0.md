# CPC Validation v0.5.0 — Physical FPGA P1

Release tag: `v0.5.0`

Research milestone tag: `cpc-physical-fpga-p1-v1`

Release date: 2026-08-16

## Summary

This release freezes the combined RFC-0001 through RFC-0009 CPC validation
baseline and the first concrete P1 execution on a Lattice iCE40 UltraPlus
Breakout Board.

The release connects the canonical lifecycle

```text
CCIR
  -> FPGA ExecutionArtifact
  -> PreparedExecution
  -> deterministic physical build
  -> retained bitstream and timing evidence
  -> guarded SRAM programming record
  -> physical stimulus and restricted LED observation
  -> ObservableExecution
  -> RFC-0009 evidence conformance
  -> independent CCIR semantic validation
```

while preserving the distinction between content identity, physical
authenticity, evidentiary completeness, and semantic correctness.

## Architecture included

- RFC-0001 CPC architecture;

The qualified execution backends are RC, Digital, and FPGA.

## Evidence location

The frozen P1 evidence and artifact-level digest index are retained under:

```text
evidence/p1/physical/
```

Regenerating derived records does not invoke the FPGA programmer. Any future
programming operation remains a separate consequential action requiring
explicit approval.

## Trust boundary and non-claims

The evidence binds the supplied photograph and its visible state. It does not
independently authenticate the photographer or capture environment.

This release does not claim:

- authenticated laboratory capture;
- hardware-rooted attestation;
- measured Fmax or dynamic latency;
- polynomial-time or constant-time execution;
- asymptotic, energy, or scaling advantage;
- complexity-class collapse; or
- superiority over conventional computation.
