# CPC Validation v0.6.0 — Open-System Execution Architecture

Release tag: `v0.6.0`

Research milestone tag: `cpc-open-system-execution-v1`

Release date: 2026-08-21

## Summary

This release extends the CPC Validation baseline from RFC-0001 through
RFC-0009 to the accepted RFC-0001 through RFC-0010 architecture.

RFC-0010 specifies the obligations for candidate driven-dissipative
open-system execution and referenced readout. The repository now contains an
execution-specification model, independent conformance validation, and a
simulated reference witness implementing the declared software contracts.

The release preserves a strict distinction between architectural
specification, simulated reference realization, and physical execution
evidence.

## RFC-0010 architecture

RFC-0010 introduces a decomposition of the candidate open-system generator
into a stabilization contribution and an instance-dependent problem
contribution.

The specification defines obligations covering:

- admissible physical representations;
- stabilization and problem-generator provenance;
- terminal silence and target-space decoupling;
- fixed-state and dark-state conditions;
- convergence and penalty-compatible decay;
- referenced physical readout;
- calibration and fixed decoding;
- realization status and evidence identity; and
- independent semantic validation.

These obligations extend the existing CPC separation between semantic
content, physical representation, execution, observation, and validation.

## Reference implementation

Version 0.6.0 adds:

- `src/open_system_execution.py`, implementing the RFC-0010 execution
  specification model;
- `src/open_system_conformance.py`, implementing independent conformance
  validation;
- `src/open_system_reference.py`, providing a simulated reference witness;
- corresponding execution, conformance, and reference-witness test suites;
  and
- integration of RFC-0010 into the repository architecture documentation.

The reference witness derives its semantic answer independently of generator
construction and records the declared realization and generator provenance.

## Relationship to the physical FPGA milestone

Version 0.5.0 remains the release that freezes the RFC-0009 P1 physical FPGA
execution evidence on the Lattice iCE40 UltraPlus Breakout Board.

RFC-0010 does not replace or retrospectively reinterpret that evidence.
Instead, it extends CPC with a separate execution architecture for candidate
open-system realizations.

The RFC-0010 implementation in version 0.6.0 is a software specification,
conformance layer, and simulated reference witness. It is not evidence of a
physical superconducting, bosonic, driven-dissipative, or other open-system
execution.

## Non-claims

This release does not claim:

- a physical realization of RFC-0010;
- superconducting or bosonic hardware execution;
- experimentally measured dissipative convergence or spectral gaps;
- experimentally validated open-system readout;
- polynomial-time or constant-time execution;
- asymptotic, energy, or scaling advantage;
- complexity-class collapse; or
- superiority over conventional computation.

Any future physical RFC-0010 realization must independently satisfy the
architecture's preparation, generator, convergence, readout, calibration,
evidence, and semantic-validation obligations.
